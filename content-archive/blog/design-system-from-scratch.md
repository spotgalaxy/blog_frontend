设计系统不是大公司的专利，个人项目同样可以从中受益。本文记录了我从零搭建一套个人设计系统的完整过程，希望能给你一些启发。

## 为什么需要设计系统

在没有设计系统之前，我的项目总是面临配色不统一、间距混乱、组件重复造轮子的问题。每开始一个新项目，都要重新决定按钮圆角多大、用什么字体、卡片间距多少。设计系统的出现，就是为了解决这些问题。

它不仅仅是一套组件库，更是一套完整的视觉语言和设计原则。有了设计系统，团队（即使只有一个人）可以更快地做出决策，减少反复讨论，把精力集中在真正重要的问题上。

> 「好的设计系统不是一次性完成的，而是在使用中不断迭代完善的。」

## 设计令牌是基础

设计令牌是设计系统的最小单元，包括颜色、字体、间距、圆角、阴影等基础变量。我用 CSS 自定义属性来实现令牌系统。

```css
:root {
  --color-primary: #b45309;
  --color-background: #faf7f2;
  --spacing-4: 16px;
  --radius-sm: 2px;
}
```

令牌的命名要遵循语义化原则，比如用 `--color-primary` 而不是具体的颜色名，这样在主题切换时只需要修改变量值。同样地，间距也应该用 `--spacing-4` 这样的语义化名称，而不是 `--spacing-16px`。

我建议从最基础的几个令牌开始：颜色、字体、间距、圆角、阴影。不要一开始就追求完美，先把最常用的定下来，在使用中逐步补充。

## 组件库的构建思路

有了令牌之后，就可以基于令牌构建组件。我采用原子设计的思路，从基础组件开始：

- 按钮：主按钮、次按钮、文字按钮
- 输入框：普通输入、搜索框
- 卡片：基础卡片、带封面的卡片
- 标签：不同颜色变体

每个组件都应该是独立的、可复用的，并且只依赖于设计令牌。这样当你修改令牌时，所有组件都会自动更新，保证了整个系统的一致性。

## 文档与使用规范

设计系统不只是组件和令牌的集合，更重要的是使用规范和文档。每个组件都应该有清晰的使用说明、示例代码，以及「什么时候不该用」的提示。

文档的价值在于降低使用门槛。即使只有你一个人在使用这套系统，好的文档也能帮你在几个月后快速回忆起当初的设计决策，避免重复踩坑。

## 总结

搭建个人设计系统是一个持续的过程。不要追求一步到位，先从最常用的组件开始，在实际项目中不断完善。重要的是建立起「系统化思考」的习惯——每做一个设计决策，都想想它能不能被抽象成可复用的规则。

当你拥有一套属于自己的设计系统后，你会发现新项目的启动速度大大加快，设计质量也更加稳定。这就是系统化的力量。
