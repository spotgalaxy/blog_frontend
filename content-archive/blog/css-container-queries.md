媒体查询的时代即将过去，容器查询才是响应式设计的未来。从基础概念到实际案例，带你全面了解 CSS Container Queries。

## 媒体查询的局限

媒体查询基于视口宽度，但组件真正关心的是「我有多少空间」。同一个卡片组件，在侧边栏里是 280px，在主内容区是 600px——用媒体查询你只能按屏幕宽度猜，猜不准是常态。

## 容器查询基础

只需要两步：声明容器，然后查询它。

```css
.card-wrapper {
  container-type: inline-size;
}

@container (min-width: 480px) {
  .card {
    display: grid;
    grid-template-columns: 160px 1fr;
  }
}
```

当容器宽度超过 480px 时，卡片自动切换为左右布局——无论它在页面的哪个位置、屏幕有多宽。组件第一次真正拥有了自己的响应式能力。

## 实战中的三个经验

**渐进增强**：容器查询的浏览器支持已经不错，但对老浏览器留一个媒体查询兜底总是稳妥的。

**容器即契约**：一旦某个元素被声明为容器，它的子元素尺寸就会受 containment 影响，布局前先想清楚谁来做容器。

**命名容器**：多层嵌套时用 `container-name` 明确指定查询对象，避免样式「查错了人」。

## 结语

容器查询改变的不仅是写法，更是组件设计的思维方式：从「适配屏幕」到「适配空间」。建议从新组件开始尝试，老代码不必急于重写。
